# Deploying SportsJack to Render

The repo carries a Render Blueprint (`render.yaml`) that runs the game server and
serves the phone app from one web service.

## First deploy

1. In Render: **New → Blueprint**, connect GitHub if asked, and pick `JB5579/Sports_Jack`.
2. Render reads `render.yaml` and proposes one web service, `sportsjack`, with a 1 GB
   disk. Approve it. It builds with `npm ci && npm run build:web` and starts with
   `npm start`; the health check is `/health`.
3. When the deploy is live, open the service URL (like `https://sportsjack.onrender.com`).
   `/build-id` shows the commit it's running.

Every push to `main` redeploys automatically.

## The plan and the disk

`render.yaml` asks for the **Starter** instance because only paid instances can keep a
disk. The SQLite database (accounts, balances, hand history, feedback, events) lives
on that disk at `/var/data/sportsjack.sqlite`. On the free instance it works, but the
database starts over on every restart or deploy, and the service sleeps when idle,
so the first visit after a quiet spell takes about a minute.

## Settings

| Variable | Default | What it does |
|---|---|---|
| `SPORTSJACK_ADMIN_TOKEN` | generated by Render | Unlocks the test-round export (see `docs/USER_TESTING.md`). Find it under the service's **Environment** tab. |
| `SPORTSJACK_REPLAY_SPEED` | 6 | Game-clock seconds per real second: a 15-minute quarter takes 2½ minutes. |
| `SPORTSJACK_BREAK_SECONDS` | 20 | Real seconds between quarters, when players can join. |
| `SPORTSJACK_REPLAY` | three 2025 NFL games | Comma-separated fixture game ids to replay. |
| `SPORTSJACK_DB` | `/var/data/sportsjack.sqlite` | Where the database lives. |
